# Vehicle / motor / harness interface requirements (rev A.17)

Everything the inverter **assumes** about what is outside it, as numbered requirements (IR-01…), each with
the value, the verifier row/finding it comes from, and the consequence if the OEM's vehicle, motor or harness
cannot meet it. Companion document: [`vendor-requests.md`](vendor-requests.md) — the same gates, from the
component-vendor side; rows there are cross-linked from here as **VR-nn**. Sources: `docs/verification-report.md`,
`docs/simulation-report.md`, `docs/firmware-contract.md` (FW-01…FW-36), `docs/design-basis.md` (§6, §8, §9, §10a,
§11), `docs/review-A15-disposition.md`, `README.md`'s gate list (①…㉘), `docs/variants.md`, `docs/dfm.md`.

## 2. Motor

The safe-state matrix (firmware-contract §6) and the resolver excitation design both run on assumed/screening
numbers. Every value in this section is a **commissioning input owed by the motor vendor** (firmware-contract
§6, "Motor data are a commissioning input (R-F16)") — gate ⑥ in the README VERIFY list is this entire section.

## 7. Safety-concept assumptions (single vs. double fault)

| ID | Requirement (value) | Reason (verifier row / finding) | If the OEM cannot meet it |
|---|---|---|---|
| IR-31 | **A battery/contactor opening during an SPO recovery interval is treated as a single fault**, not stacked with the inverter fault that caused the interval — it can be caused by the inverter's own fault, a crash, a CAN loss or a full/cold pack, and the design credits it as such (not as an independent second failure requiring separate mitigation). The intervals covered: the ≥ 1.5 ms FLT_HS reset, an FLT_LS SPO until n < n_x, a V5GD loss, and a total LV loss. | firmware-contract §6, "Motor/vehicle release rule for SPO energy" (round 9, A8-G02): "A battery that opens inside such an interval is **not** treated as an independent second fault... a motor/vehicle combination is released only when [rule (a), (b) or (c)] holds." | This is the load-bearing assumption behind IR-05 and IR-10: the OEM's motor/vehicle combination must satisfy rule (a), (b) or (c) for **every** one of these intervals, not just the ones that feel most likely — "otherwise that motor is not released with this inverter" (§6, closing line). There is no partial credit for "usually the battery stays connected." |
| IR-32 | **Total LV (KL30) loss is the single fault the rule-(a)/(c) analysis is built around** (IR-05); it is **not** assumed to occur simultaneously with an independent second failure. The rule-(c) HV-fed backup-bias option, when fitted, covers **only** this case — it explicitly **cannot** restore ASC for a V5GD loss (masked by design) or for a lost power-board LV feed. | firmware-contract §6, rule (c): "For total KL30 loss only, the HV-fed backup-bias ASC option is fitted. It cannot restore ASC for the V5GD row... or for a lost power-board feed (R9X-09)." | If the OEM's integration needs ASC availability through a V5GD loss or a power-board LV-feed loss (as opposed to total KL30 loss), the backup-bias option does not help — those rows rest on rule (a) alone (the motor's own energy-safety at every speed), with no rule-(c) escape. This must be understood before specifying the backup-bias option as "the fix" for LV-loss coast-down risk in general. |
| IR-33 | **A double fault is explicitly named exactly once** in the safety concept: an FS1B-ASC entry (MCU dead, EN low) concurrent with a **new** high-side short. Because EN is low on this path, that new short is "not bounded by the low-side DESAT" the way it would be under PWM-ASC (EN high) — firmware-contract §4c calls this out by name as the one double-fault case the design does not claim to cover, pending a NOVOSENSE statement (VR-08) that could remove or narrow it. | firmware-contract §4c: "a high side that fails short during an FS1B-ASC is not bounded by the low-side DESAT. That takes a double fault... Until then, FW-12 chooses FS1B-ASC only for motors that need it (§6)." | If the OEM's motor/vehicle combination requires unconditional FS1B-ASC (rather than the current motor-dependent restriction), this exact double-fault case is what stands between "restricted" and "unconditional" — it is closed by VR-08 (a NOVOSENSE statement), not by anything the OEM's vehicle integration can do on its own. |
