# Target bring-up checklist (silicon / RM / RTD / HIL / EOL)

This is the one list of what the host build cannot prove. Every open item of the firmware is here and
nowhere else (round 17): each row names what must be read in the S32K39 reference manual (RM) or bound
against the installed RTD / S32 Config Tools project, or measured on silicon, HIL or at EOL; the check that
closes it; and what holds the image closed until then. Contract decisions are in
`docs/firmware-contract.md` (§10c lists them); this page holds only what needs the hardware.

Every marker in the firmware sources has a row here, cited as `file:line`, and every `file:line` cited here
is a marker: `make target-check` fails when the two drift apart. Marker kinds: **RTD** bind against the RTD
release and the Config Tools project; **RM** read in the S32K39 RM; **HW-RM** read in the RM and confirm on
silicon; **HW** measure on the target; **EOL** an EOL/HIL station record; **REL** the release/product build.

**What always holds.** Arming needs the five FW-24 evidence items (route bound, configuration read back,
REG_PROT locked, and the EOL/HIL record for this `TI_FW_ID`, SKU and device UID) and a valid layout-4 (round 23, FW-45/FW-46; layout 3 before them)
calibration record; anything missing is a DTC, no FS0B release, no FW-16 energisation, no `MCU_GATE_EN`, and
INV_STATUS byte 15 names it. A target build with an unfilled board configuration does not compile. A
`make target-check` build (no RTD) returns the safe default from every HAL call and never arms.
